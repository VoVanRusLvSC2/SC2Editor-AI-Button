# План подключения Codex, Claude и MCP

Окно AI пока показывает интерфейс и состояние «Не подключён». Оно ещё не читает историю, не отправляет сообщения и не обращается к MCP.

## Архитектура

DLL отвечает за окно редактора. Отдельный локальный процесс управляет подключениями и сообщениями, чтобы не блокировать интерфейс и независимо обновлять интеграции. Локальный канал должен проверять пользователя. В окне нужны список доступных чатов, переписка, отправка и остановка ответа, ошибки, переключатель Codex / Claude и отображение запросов разрешений и операций MCP.

## Codex

- Подключить установленный Codex через официальный app-server и согласовать авторизацию с поддерживаемым способом установленной версии, не извлекая токены приложения из файлов.
- Использовать `thread/list` для доступных чатов, `thread/turns/list` для истории, `thread/resume` и `turn/start` для продолжения. Отображать поток ответа, операции и запросы подтверждений.
- Проверить на этом компьютере, какие существующие чаты доступны и можно ли продолжить выбранный чат приложения. Облачные и удалённые чаты могут требовать отдельного подключения; полная синхронизация пока не подтверждена.
- Документация: https://developers.openai.com/codex/app-server/ .

## Claude

- Подключить Claude Code через официальный Claude Agent SDK и поддерживаемую авторизацию. SDK предоставляет список локальных сессий, чтение сообщений и продолжение сессии.
- Проверить установку, вход пользователя и доступные сессии. Чаты веб-приложения Claude и локальные сессии Claude Code — разные источники; доступ ко всем веб-чатам не предполагается.
- Показывать запросы на инструменты и разрешения. Документация: https://code.claude.com/docs/en/agent-sdk/sessions и https://code.claude.com/docs/en/headless .

## MCP редактора

- Использовать настроенный пользователем SC2 Editor MCP для выбранного провайдера. Проверять соединение, доступные инструменты, экземпляр редактора и текущую карту; показывать ошибки подключения.
- Отражать операции и подтверждения в диалоге. Проверить переподключение MCP и смену карты для обоих провайдеров.

## Этапы проверки

1. Посредник: запуск, остановка, обработка ошибок и проверка версий; окно остаётся отзывчивым при отключении.
2. Codex: список доступных чатов, история, новый диалог, продолжение выбранного, поток ответа и подтверждения.
3. Claude Code: авторизация, локальные сессии, создание и продолжение, поток ответа и подтверждения.
4. MCP: статус, запрос к тестовой карте, переключение карты и восстановление соединения.
5. Проверка в Terrain, Triggers и Data и при изменении размера окна. Расширение экспериментальное: его окно не является зарегистрированным внутренним модулем редактора.
